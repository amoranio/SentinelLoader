SentinelLoader

01 — Connect

Point this machine at Sentinel.

Custom logs land in a Log Analytics table. You can parse files with no Azure account, let this app create the table, or finish Azure yourself and only paste credentials here.

Identity

A service principal is the usual choice. Use Azure CLI only if this app runs on a machine where you have already signed in with az login.

02 — Files

Drop the logs.

CSV, TSV, JSON, or JSONL. Multiple files go to one table. Encoding and delimiter are detected; override only if the preview looks wrong.

    Path A — let the app create the table
    
          
    The Logs Ingestion API will not invent a table at upload time. SentinelLoader can create {Name}_CL and a Direct DCR if this identity can manage the workspace.
    
          
      
            
    1. Create an Entra app registration (name it SentinelLoader). Add a client secret and copy the secret value immediately.
      2. 
            
    2. Copy Tenant ID, Client ID, Subscription ID, resource group, and Log Analytics workspace name.
      3. 
            
    3. Grant the app:
              
        
                
      • Log Analytics Contributor on the workspace (create the table)
        • 
                
      • Monitoring Contributor on the resource group (create the DCR)
        • 
                
      • User Access Administrator on the RG or DCR (so it can grant itself ingest permission)
        • 
              
      
            
      4. 
            
    4. In this app: choose App creates the table, paste those values, Save & test, then parse and send.
      5. 
          
    
          
    If role assignment fails, grant Monitoring Metrics Publisher on the new DCR to the same app, then send again with “Use a table I already created.”
    
        
    

        
    
          
    Path B — create the table in Azure, then only paste details here
    
          
    Use this when a SOC engineer should own the table, or the app identity is not allowed to create resources. When you are done, this app only needs credentials plus three DCR fields.
    

          
    1. Create a service principal
    
          
      
            
    1. Azure portal → Microsoft Entra ID → App registrations → New registration.
      2. 
            
    2. Name e.g. SentinelLoader. Single tenant is fine.
      3. 
            
    3. Certificates & secrets → New client secret. Copy the Value (not Secret ID).
      4. 
            
    4. From Overview, copy Application (client) ID and Directory (tenant) ID.
      5. 
          
    

          
    2. Build a sample JSON (do this in SentinelLoader first)
    
          
      
            
    1. In this app, choose Preview only, drop your CSV, parse, and open Validate.
      2. 
            
    2. Confirm columns and TimeGenerated.
      3. 
            
    3. Click Download sample JSON for Azure portal. The portal wizard needs a JSON array of example records, not the CSV itself.
      4. 
          
    

          
    3. Create the custom table (DCR-based)
    
          
      
            
    1. Azure portal → Log Analytics workspaces → the workspace used by Microsoft Sentinel → Tables.
      2. 
            
    2. Create → New custom log (DCR-based). Do not use the legacy MMA custom log.
      3. 
            
    3. Enter a table name. The portal appends _CL. Pick plan Analytics unless you know you need Basic/Auxiliary.
      4. 
            
    4. Create a new Data Collection Rule in the same region as the workspace. If the wizard asks for a Data Collection Endpoint, create one (Monitor → Data Collection Endpoints) in that region, or use an existing DCE.
      5. 
            
    5. Upload the sample JSON you downloaded. If there is no TimeGenerated field, the portal will add a transformation — prefer mapping your timestamp column to TimeGenerated instead.
      6. 
            
    6. Create. Wait until the table shows as ready (often 1–2 minutes).
      7. 
          
    

          
    4. Grant the app permission to ingest
    
          
      
            
    1. Azure portal → Monitor → Data Collection Rules → the DCR from the wizard.
      2. 
            
    2. Access control (IAM) → Add role assignment.
      3. 
            
    3. Role: Monitoring Metrics Publisher.
      4. 
            
    4. Assign access to the SentinelLoader app registration (search by name or client ID).
      5. 
          
    

          
    5. Copy the three ingest values
    
          
      
            
    1. DCR → Overview → Immutable Id (dcr- + hex).
      2. 
            
    2. DCR → JSON View (latest API version) → properties.logsIngestion.endpoint, e.g. https://….ingest.monitor.azure.com.
      3. 
            
    3. Same JSON → properties.streamDeclarations keys. The stream name is that key, typically Custom-YourTable — not Custom-YourTable_CL unless that is what the JSON actually shows. Match it exactly.
      4. 
          
    

          
    6. What you type into this app
    
          
      
            
    • Connect: Tenant ID, Client ID, Client secret, Subscription ID, resource group, workspace name
      • 
            
    • Send → Use a table I already created: table name (_CL), DCR immutable ID, ingestion endpoint, stream name
      • 
          
    
          
    You do not paste the CSV into Azure. This app still parses files and POSTs them to the Logs Ingestion API.
